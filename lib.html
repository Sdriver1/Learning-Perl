lib.pl   a simple perl library

lib.pl is a library of useful subroutines and functions that anyone can use. If you read and follow the directions, they should all work, however, they are not hacker-proof, or certified "monkey proof." Of course with most software, there are no guarantees, warranties, explicit or inferred with this package. These subroutines are not meant for professionals. If you program for a living than would consider this library "baby talk." However, for the beginner, this is a good group of interesting routines that will help in many ways.

&check_email($address) -- checks the form of an email address given to it as an argument. If it has the correct form it returns a 1, if not: it returns 0. Perfect for if statements.

&send_mail($mailprog, $to, $from, $subject, $body0, $body1, $body2,...$bodyXX)-- sends mail to whoever, needs input in the following form or variables named as above defined with the neccessary information.(e.g. $to = 'joebob@aol.com') and so on. If you want to put the body as an argument you must include the to, from, and subject variables, as it reads them in order. (first the to, then the from, then the subject). Check out the source code and see for yourself how it works. Can take an unlimited number of body variables, which can any combination of alphnumeric characters, variables, and/or arrays. Before the message is written the body variables are all appended to one variable and are separated in the message by a "\n" character.

I suggest you have $mailprog defined in the main script (i.e $mailprog = '/usr/lib/sendmail'; which is the most common) or wherever it is located on your server.

For emailing a small number of people a personalized message, I suggest you use this subroutine in a form like: 

    for ($i = 1; $i <= $#emails; $i++)
    &send_mail($mailprog, $emails[$i], $from, $subjects[$i], $headers[$i], $body, $footers[$i], $signaturefile)

If you have generated a list of people, you can enter their information in arrays and send them personalized email updates, greetings, confirmations of reservations, or whatever. For big lists, use the Bcc version.

&random(@thing) -- Random picker. Picks an element from an array named @thing or a random number between 1 and a given number. If the parameter is not an array or scalar number, then the parameter is just returned (i.e. &random('jimmy');  would return "jimmy").

Suggested usages:

1. print "Location: &random(@redirect)\n\n";
2. if (&random(10) > 5){
3. <img src = "&random(@images)">
4. print "You are visitor number: &random(9001) + 999 since &random(@month) &random(31),
	&random(5) + 1994"

-- generates a number between 1000 and 10000 and a date between January 1, 1995 and December 31, 1999; and you could get dates like Febraury 31, 1997.

&append($filename, $line1, $line2,...$lineXX) -- will append a file (assuming the file is writable, with the parameters given. The parameters are written right after one another--no default line breaks, however line breaks may be added inside the parameters, or can be a parameter itself. If the file does not exist, it will be made.

&read($filename, $number_of_lines) -- will read a file given by the parameter and a certain number of lines given by the other parameter, and returned as a list array. If the "$number_of_lines" parameter is omitted, then the entire file will be read into the array. Line breaks can be erased with the code:

chomp (@array = &read('textfile.txt', 3400));   # will read 3400 lines of textfile.txt

chomp (@array = &read('textfile.txt'))          # will read the entire file into the array

&slurp($filename) -- will read an entire file and return as a single scalar variable with line breaks

$file = &slurp('textfile.txt');

&dayofweek($month,$day,$year) -- will determine and return the day of the week of the date given. Month day and year must be in that order (as separate parameters - note the commas). It is Y2K, Y3K, Y4K ... compatible.
Parameters: $month must be a number between 1 and 12 or at least a three letter abbr. for a month (Jan, Feb, Mar...). Case is not important and you may use the full month name if your code requires it. $day must be a number between 1 and the number of days in that month, taking into account the leap year. There is no syntax error checking for the year (except that it must be . It supports negative numbers -373 is read as 373 BC (there was no year 0 and the routine will not take it as a parameter. If a bad day (one that does not exist - e.g. 2/30/1995) is entered, the script will return 0, allowing one to use this as a check ( if &dayofweek($m, $d, $y) { ... )
Also supports a fourth parameter which if any value but 0 or null will return the string as an abbrevation (i.e. Mon, Tue, Wed...), instead of the full day name.
Takes advantage of the fact that the calendar repeats itself every 400 years. Jan. 1, 2000 is a Saturday as well as 1-1-1600, 1-1-1200, 1-1-2400 and so on.

Great for finding useless information, too. Like every Friday the 13th in the last millenium

for ($y = 1001; $y <= 2000; $y++){
  for ($m = 1; $m <= 12; $m++){
    if (&dayofweek($m,13,$y) =~ /Friday/){
       print "Friday, $m\/13\/$y\n";
    }
  }
}

&time('time','date','mdy','sec')  --  returns the time in the form - "12:24 PM   Friday, January 5, 2000" by default (no given parameters). The parameters shown can be put in any order and each return a different value. 'time' and 'date' return the default values (shown). 'mdy' returns the date but in the compact 1/5/2000 form. If sec, (seconds, secolanda, or even secccccccccccccccconds) is entered anywhere (just looks for "sec") then the seconds will be returned as well, and be put after the minutes like this: 12:24:43 PM
The code shown above in the example would return:

        12:24:43 PM   Friday, January 5, 2000   1/5/2000

As you can see, the elements returned are in the order they are given as parameters.

&is_between($time1,$time2,$time3,$time4)  --  will determine if the two time intervals ($time1 to $time2 and $time3 to $time4) conflict with each other. $time4 is optional, and if omitted it will determine if $time3 is between $time1 and $time2.
All times must be in military (24 hour) format.

&is_between('0645','0745','2345',0145') would return '0' as these periods do not conflict

--------------------------------------------------------------------------------

&timeplus($time,$min)  --  will return the time plus the number of minutes given by $min. $time can be in military (24 hour) or regular (12hr:AM/PM) format. $min can be negative and it will go back

&timeplus(2347,134) would return "0201"
134 min past 11:47PM => 2:01AM

--------------------------------------------------------------------------------

&timeformat($time)  --  will convert military (24hr) to normal (12hr, AM/PM) format and vice-versa

&timeformat('2347') would return "11:47PM"
&timeformat('5:47PM') would return "1747"

&file_contains($filename, $string, $minimum) -- returns the number of times in which $string is found in the file: $filename. or, if $minimum is given, returns that number (if found atleast that many times) or zero. Good for if statements for determining if you want to append a file if it doesn't already contain someone's name or email. Also can be used for determining the number of links, type of a particular tag or whatever, in a web page.

&list2string($sort, $listdelimiter, @list) -- returns a scalar string element containing the list values. The value of $sort will tell the subroutine how to sort the list ('random' for random, 'backwards' for a last to first element listing). If it is a value other than 'random' or 'backwards' it will list them from the first to the last element. $listdelimiter will be what separates each element in the string. Useful ones may be the tab "\t", newline "\n", space ' ', or if working with HTML, the line break tag: '<br>'. You may also want to put a newline on it as well for readability of the HTML source. If left undefined, '' or 0 (zero), all elements will be run together. The list given as a parameter can be an array (@list), part of an array (@list[1..87]), or any combination of lists and strings:

&list2string(0,"\n",$htmlheader,'<body><p>',@list[0,45],'</p><p>',$dynamicmaterial,@list[54,90],$footer)

You can nest the strings created with the function, in the function again and again and it should be able to handle it.

&derivative($x-value, $function) -- returns the numerical derivative of any function or polynomial. For Polynomials, &derivative($x-value, $zero-order-coeff, $1st_order_coeff, ..., $nth_order_coeff) is all you need, just the coefficients. If you want the coefficients of the polynomial's derivative just have the first paramenter equal to 'coeff'. &derivative('coeff', @coefficients) or use the function below.

&derivative(3,0,0,1) would return 6, as the polynomial given is just: y = x2 and the derivative is of course: dy/dx = 2x and therefore at x = 3, dy/dx = 6.

***** VERY IMPORTANT!!! The variable MUST be x or $x.

while you can put any expression into this subroutine, I seriously suggest taking all polynomials out and handling them with a separate &derivative function call (much faster and better accuracy).

         you write it as: &derivative('coeff', 6,-18,5,0,4) or &derivative_coeff(6,-18,5,0,4)

&integral($xi, $xf, $function) -- returns the numerical integral value of any function (must be in terms that Perl can understand - e.g. $function = '4*x**4 - 5*x**2 + 4 + (log (x+34.23))**3'; would work.

Uses Romberg's method: the trapezoidal (linear) numerical integration algorithm, plus an approximation of the error based on the fact that the error is nearly proportional to the square of the step increment, h2, so halving h and reapplying the the rule reduces the error by a factor of 1/4. Then an extremely accurate estimate of the true value can be determined from comparing the two values. This function actually integrates 3 times and produces two very accurate values, then compares these values to produce the final answer. I suggest that you let this function handle non-polynomial parts of the function and let the 100% accurate polynomial integrator handle the polynomials.

&integral($xi, $xf, @coefficients) -- returns the integral of any polynomial, exactly.

The variable again must be x or $x.

Note: 

For several polynomials I was able to check using the above function, this function was accurate to about 12 significant digits, if not completely accurate. I was also able to accurately check most other functions (sin, cos, log, and combinations of them with others) with the integration function on my TI-82, although I have no way of knowing how accurate the calculator is. For most functions where the values do not fluctuate too much, this should be an excellent numerical approximation.

&raddeg(135, 'rad', 'reduce') -- returns the equivalent radian value of the degree value given or vice-versa. If the value of the second parameter is 'rad', it returns the value of the first parameter in radians (assuming it is degrees). If the second parameter is 'deg', then the value in degrees of the first parameter (assuming it is in radians) is returned. If the third parameter has the value 'reduce' it will chop off integer multiples of 360°/2p radians untill the returned value is under 360°/2p rad. This is most useful in translating degree values into something you can use the sin and cos functions (both built into Perl) with and translate back to degrees for readability by the user - they may have a better idea what 160° rather than 2.7925 radians is (they are the same angle).

&placevalue(345728273,5)
&placevalue($value,$i) -- returns the integer in the 10 to the $i place of $value
The top would return 7, as it is in the 100,000's place. Handles floating point numbers too.

&placevalue(728273.785,-3) would return 5. The precision tops out at around the 12th place, starting from the beginning of the number. &placevalue(87654321.1234,-4) will not return 4, as the 10-thousanth's place is out of the 32-bit realm. The places above it would be fine.

Here's a way to figure how much precision Perl can handle on a floating pt. number. Move the decimal point until the integer part reaches 2^31, about 2 trillion (2e12). Yes there are 32 bits but the first is used to determine if the number is positive or negative. Just before it goes above that value, whatever digit is in the one's place is as far as it will go. After that, the actual stored digits are not guaranteed accurate.

***NEW FEATURE***
entering the number as a string variable will allow almost infinite precision. This allows use with the BigFloat and BigInt modules. Your string can be an integer: "98765432109876543210", or a floating pt. number: "9876543210.1234567890123456789", or an scietific notation number (standard notation for BigFloat and Int): "9876543210.123456789E-17"
As always, the second parameter will be the place value as 10 to the $_[1] power.

example:
&placevalue("9876543210.1234567890123456789",-17); will return "7"
